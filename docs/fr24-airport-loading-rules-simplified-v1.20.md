# FR24 风格机场分层加载规则需求文档 1.20

## 1. 文档定位

本文档用于重新整理地图中机场在不同缩放层级下的加载、显示和标签规则。目标不是复刻 FR24 的内部实现，而是基于 FR24 公共页面可观察到的行为，总结出一套更简单、更稳定、更适合本项目的机场展示规则。

建议归属版本：`1.20`。
形成日期：2026-08-12。

本版本明确废弃 1.18 中复杂的网格密度预算、综合打分阈值和多重比例尺折算逻辑，改为“少层级、强约束、按视口渐进加载”的实现方式。

> 比例尺说明：实现中的 `effectiveScaleKm` 表示地图上 100 个 CSS 像素对应的实际距离，不等同于地图底部比例尺条的文字值。以下阈值已用 FR24 页面实际比例尺条校准。

## 2. FR24 公共页面可观察结论

基于 FR24 公开支持文档和公开博客页面，可确认以下机场展示规律：

- 蓝色机场点代表有常规每日定期客运航班、且通常处于 FR24 覆盖区域内的机场。
- 地图上的机场 marker 支持在设置中调整可见性。
- 点击机场 pin 后，可以查看到达/出发、地面飞机和天气信息。
- 本项目 1.20 起不再展示地图常驻机场文字标签；高缩放级别也只保留机场 pin 与停场数量角标。
- 鼠标悬停在机场 pin 上时，仍可看到机场名称和代码。

公开来源：

- [Flightradar24 Support: What are the blue points on the map?](https://support.fr24.com/support/solutions/articles/3000115501-what-are-the-blue-points-on-the-map-)
- [Flightradar24 Blog: New Flightradar24.com label options](https://www.flightradar24.com/blog/inside-flightradar24/new-flightradar24-com-label-options/)

## 3. 设计原则

### 3.1 只保留三个核心目标

1. 远景时地图要干净，不能被机场点铺满。
2. 中景时机场要有层级，不能所有机场同权。
3. 近景时要能看全当前视口内的机场。

### 3.2 不再使用的复杂规则

以下规则在新方案中不再作为主逻辑：

- 多层 `displayLevel` + 网格截断叠加。
- 复杂的密度预算表。
- 过多的综合评分字段。
- 用比例尺、纬度、视口面积一起计算的高复杂度阈值。

## 4. 机场层级定义

建议将机场仅分为四层，前后端都按这四层理解。

| 层级 | 名称 | 含义 | 默认展示策略 |
| --- | --- | --- | --- |
| L1 | 核心机场 | 国际枢纽、主要公务机枢纽、全球高频机场 | 远景可见 |
| L2 | 重要机场 | 国家级、区域级、核心商务机场 | 中景可见 |
| L3 | 常规机场 | 城市周边、普通运行机场 | 近景可见 |
| L4 | 近景机场 | 小型机场、低频机场、通航机场 | 约 50km 及更近时可见 |

说明：

- 层级必须由后端优先提供。
- 前端只做轻量兜底，不做长期推断。
- 如果机场同时满足多个业务条件，优先提升层级，而不是增加额外维度。

## 5. 分层加载规则

### 5.1 远景层

适用范围：

- 世界视图
- 大洲视图
- 国家总览视图

显示规则：

- 当比例尺条约为 `500km` 或 `200km` 时，`auto` 模式不显示普通机场 pin，保持与 FR24 默认大范围地图的视觉密度一致。
- 当比例尺条约为 `100km` 时，首次显示第一批核心机场 pin；实现阈值设在 `effectiveScaleKm` 约 `300`，位于 `200km` 隐藏档和 `100km` 首次出现档之间。
- 用户主动打开机场图层（`on`）时，远景最多显示 L1 机场。
- 机场只显示 pin，不显示完整文字标签。
- 默认地图上不应出现成片机场 pin；机场数量应明显少于飞机数量。
- selected airport、搜索结果机场不受隐藏规则影响。

### 5.2 中景层

适用范围：

- 国家局部视图
- 大区域视图
- 城市群外层视图

显示规则：

- 比例尺条约为 `100km` 至 `50km` 时，显示第一批 L1 机场；按当前地图换算对应 `effectiveScaleKm` 约 `455` 至 `110`。
- 比例尺条约为 `50km` 或更近时，当前视口内显示 L1-L4 机场 pin。
- 默认仍以 pin 为主。
- 不显示常驻机场代码标签。
- 不显示常驻完整机场名称。
- 机场数量可以增加，但不能覆盖地图主体信息。

### 5.3 近景层

适用范围：

- 城市群视图
- 机场群视图
- 约 50km 级别及更近视图

显示规则：

- 显示 L1 + L2 + L3 + L4 机场。
- 当前视口内可见机场应全部进入渲染队列。
- pin 继续保留，常驻文字标签继续隐藏。
- 只有 selected / hover / search 命中的机场才强制显示完整信息。

### 5.4 选择态优先级

以下对象永远优先于普通机场密度规则：

1. 当前选中的机场
2. 搜索定位机场
3. 飞机详情中的出发机场和到达机场
4. hover 命中的机场

这些对象即使在远景层，也不能因为密度限制被直接隐藏。

## 6. 标签显示规则

### 6.1 标签层级

1.20 起地图常驻机场文字标签取消，不再按缩放层级展示机场名称、IATA 或 ICAO。

信息展示只保留两类交互态：

| 状态 | 显示内容 |
| --- | --- |
| Hover | 机场中文名、英文名、`IATA / ICAO` |
| Selected | 固定机场信息浮窗与左侧详情面板 |

### 6.2 Hover 与选中

- hover 机场时显示完整名称和代码。
- selected 机场时显示完整信息。
- 标签出现和消失必须有轻微淡入淡出，避免闪烁。
- 标签碰撞优先于普通 pin 隐藏，不影响 selected 和 search 结果。

## 7. 加载与刷新方式

### 7.1 只按视口加载

机场请求应按当前地图视口加载，不应一次性拉取全量机场。

建议规则：

- 地图拖拽中不发起大请求。
- 地图停止后，在 `idle` 阶段再请求当前视口机场。
- 请求范围应包含少量缓冲区，避免快速拖动时频繁重拉。
- 进入新视口后只做差量更新，不要清空后重建。

### 7.2 缓存

机场基础数据应单独缓存，和飞机实时数据分离：

- 机场基础信息：长缓存
- 当前视口机场列表：中缓存
- 机场详情面板数据：短缓存

### 7.3 细节懒加载

机场信息面板中的到达、出发、天气、地面飞机等内容应按需加载，不应在地图层级加载时同步触发。

## 8. 交互规则

### 8.1 点击机场

点击机场 pin 后：

- 地图聚焦到该机场
- 左侧或侧边面板打开
- 默认展示 arrivals / departures / ground aircraft / weather 等信息

### 8.2 机场可见性设置

保留机场图层开关：

- `auto`：按本规范自动分层
- `on`：允许更多机场进入当前层，但仍受近景逻辑约束
- `off`：隐藏普通机场，仅保留 selected / search / route 语义对象

### 8.3 视觉优先级

地图中图层关系应保持：

1. 飞机 marker
2. 选中飞机高亮态
3. 机场 pin
4. 机场标签
5. 底图地名

## 9. 验收标准

### 9.1 远景验收

- 地图在大范围视图下不会被机场点铺满。
- 机场数量明显收敛。
- 只显示核心机场。

### 9.2 中景验收

- 进入国家/区域视图后，机场数量逐步增加。
- 机场以 pin 为主，代码标签受控。
- 不出现大量完整名称标签遮挡地图。

### 9.3 近景验收

- 接近 50km 级别时，当前视口内机场全部可见。
- selected / hover / search 机场始终可见。
- 标签碰撞正常，地图仍可读。

### 9.4 点击验收

- 点击机场后能够打开机场信息。
- 能看到到达、出发、地面飞机和天气入口。

## 10. 结论

新的机场加载规则应以 FR24 的公开可见行为为准，核心就是：

- 远景少量核心机场
- 中景逐步扩展机场层级
- 近景全量显示当前视口机场
- 标签由完整名称逐步收缩到代码，再到仅 pin
- 选中态和搜索态永远优先

这份文档可作为后续机场加载规则实现和控制台配置的统一依据。
