# 网络消耗排查与优化方案 v1.21

## 结论

当前版本的快速流量消耗不应只归因于地图底图。代码排查显示，持续消耗更可能来自 `513008` 实时快照轮询；地图底图主要在首次加载、拖拽、缩放、切换视野时产生明显流量。

## 已定位的主要流量来源

### 1. `513008` 实时快照轮询

相关位置：

- `app.js:7408` `buildAircraftViewportRequest`
- `app.js:7588` `aircraftRefreshIntervalMs`
- `app.js:7673` `refreshRealtimeData`
- `data-service.js:227` `postForm`

当前行为：

- 飞机实时数据通过 `513008` 持续轮询。
- 普通状态约每 `4.2s` 请求一次，约 `857 次/小时/页面`。
- 选中飞机时约每 `2.5s` 请求一次，约 `1440 次/小时/页面`。
- 高缩放机场场景约每 `3s` 请求一次，约 `1200 次/小时/页面`。
- 页面隐藏后仍约每 `22s` 请求一次，约 `164 次/小时/页面`。

风险点：

- 当前配置 `showAllAircraftIconsAtAllZooms: true`。
- 飞机请求范围会切到全球范围，`aircraftScope: "global"`。
- 请求上限 `allAircraftIconRequestLimit: 50000`。
- 请求参数同时带 `includeAircraft: true` 与 `includeAirports: true`，可能导致实时飞机和机场数据被一并返回。
- 即使地图不动，也会持续消耗接口返回体流量。

### 2. 机场快照请求

相关位置：

- `app.js:7358` `buildAirportViewportRequest`
- `app.js:7626` `refreshAirportData`
- `app.js:16783` 初始化调用

当前行为：

- 初始化时会调用一次机场快照。
- 之后约每 `300s` 请求一次，约 `12 次/小时/页面`。
- 机场请求上限为 `50000`。

风险点：

- 初始化阶段 `refreshAirportData("init")` 和 `refreshRealtimeData("init")` 连续调用，二者都走 `513008`。
- 飞机快照请求中又带了机场元数据，存在首屏重复加载空间。

### 3. Google Map 底图加载

相关位置：

- `app.js:3930` `loadGoogleMaps`
- `app.js:3979` Google Maps JS API 加载
- `app.js:3230` `new google.maps.Map`

当前行为：

- 默认使用 Google Map。
- 首次加载会下载 Maps JS、marker 库、地图样式与瓦片/矢量资源。
- 拖拽、缩放、定位跳转时会继续请求新的地图资源。

判断：

- 如果页面静置仍持续高速耗流量，优先检查 `513008`。
- 如果只有拖拽/缩放时流量激增，优先检查 Google Map 瓦片。

### 4. Leaflet CDN 资源

相关位置：

- `index.html:9` 外链 Leaflet CSS
- `index.html` 末尾外链 Leaflet JS

当前行为：

- 即使默认使用 Google Map，也会加载 Leaflet 资源作为降级能力。

风险点：

- 属于一次性流量，体量不大，但可优化。

## 建议的诊断手段

### A. 增加仅本人可见的流量调试台

建议复用现有 `apiDebugConsole` 授权机制，新增 `trafficDebug` 模块：

- 统计每个接口 `pid` 的请求次数。
- 统计每次请求的响应字节数。
- 按来源聚合：`513008`、`513009`、`513010`、`513011`、`513013`、`513014`、`513015`、Google Map、静态资源。
- 展示最近 5 分钟、最近 30 分钟、当前页面累计流量。
- 标记请求触发原因：`init`、`timer`、`viewport`、`visible`、`airport-timer`。
- 线上默认关闭，仅允许白名单账号通过 `?trafficDebug=1` 打开。

### B. 用浏览器 Network 做一次对照采样

建议采样三组场景：

1. 首次打开后静置 5 分钟。
2. 保持打开并点选一架飞机 5 分钟。
3. 连续拖拽/缩放地图 2 分钟。

需要记录：

- 总流量。
- `513008` 流量占比。
- Google Map 域名流量占比。
- 单次 `513008` 平均响应体大小。
- 每分钟请求数。

## 优化策略 v2：当前视窗优先，非视窗降频

本策略目标是在不影响用户当前视图实时观感的前提下，降低持续流量与恢复页面时的突发流量。

### 本轮已落地

1. 飞机实时快照从 `global` 改为 `viewport`
   - 全缩放级别展示飞机 icon 的视觉规则保留。
   - 但不再为了全缩放展示而请求全球飞机。
   - 请求范围改为当前地图视窗加 `0.15` padding。

2. 飞机快照改为轻量地图模式
   - 请求中新增 `requestTier`、`payloadMode: minimal`、`fields: map`。
   - 飞机实时快照不再默认夹带机场列表，`includeAirports` 改为 `false`。

3. 视野变化阈值
   - 地图中心移动不足当前视窗 `18%` 时不重新请求。
   - zoom 变化不足 `0.5` 时不重新请求。
   - 拖拽/缩放过程中继续使用本地缓存绘制，避免交互卡顿。

4. 隐藏页降频与暂停
   - 页面隐藏后实时刷新间隔降到 `60s`。
   - 隐藏超过 `5min` 后停止继续排队刷新。
   - 隐藏期间不会累计需要补跑的请求。

5. 恢复可见的加载顺序
   - 用户回到页面时优先刷新当前飞机视窗。
   - 机场快照如需刷新，延迟 `6s` 后再请求。
   - 隐藏前的过期请求会被失效，不允许回来后覆盖新视图。

6. 增量版本使用边界
   - 只有同一视图内的 `timer` 刷新继续携带 `sinceVersion`。
   - 地图视野变化、页面恢复、首屏初始化不复用旧视野版本号。
   - 避免后端按旧视野增量返回，导致新视野数据不完整。

### 设计原则

1. 当前视窗优先
   - 用户正在看的地图视窗内飞机，继续保持接近实时的更新体验。
   - 当前视窗内飞机使用较高刷新频率、较低延迟、优先渲染。
   - 当前点选飞机单独进入高优先级通道，航迹与当前位置保持连续。

2. 非当前视窗降级
   - 当前视窗外的飞机不需要和视窗内飞机保持同等刷新频率。
   - 非视窗飞机只保留用于快速切换视野的轻量状态，例如唯一键、最后位置、航向、注册号、更新时间。
   - 稳定字段、详情字段、航迹字段不随全局刷新返回。

3. 不积压历史刷新
   - 页面隐藏、用户长时间未浏览、设备锁屏后，不累计未执行的轮询任务。
   - 用户回到页面时，只执行一次恢复刷新，不补跑隐藏期间错过的每一轮刷新。

4. 交互优先于加载
   - 地图拖拽、缩放过程中优先使用本地缓存即时绘制。
   - 数据请求不得阻塞地图移动、缩放、图标旋转、标签显示。
   - 视野稳定后再发起一次轻量请求，并且允许取消过期请求。

### 请求分层

建议把飞机数据拆成四个请求层级：

1. `visible-live`
   - 范围：当前视窗加少量 padding。
   - 内容：地图渲染必要字段。
   - 频率：前台普通状态 `4s-6s`；选中飞机状态 `2.5s-4s`。
   - 目标：保证用户眼前飞机位置更新及时。

2. `selected-live`
   - 范围：当前点选飞机。
   - 内容：当前位置、航向、速度、高度、当前航段、航迹增量。
   - 频率：`2.5s-4s`。
   - 目标：保证左侧弹窗、航线、注册号标签的实时性。

3. `offscreen-lite`
   - 范围：当前视窗外但仍在页面缓存中的飞机。
   - 内容：最小状态字段，不返回详情、不返回航迹。
   - 频率：前台 `30s-60s`；页面隐藏后 `3min-10min` 或暂停。
   - 目标：用户切换视野时有基础缓存，但不持续消耗大流量。

4. `metadata-detail`
   - 范围：用户点选飞机、点选机场、打开详情 tab 时。
   - 内容：飞机基础信息、机场基础信息、历史行程、航迹详情。
   - 频率：懒加载并缓存 `5min-30min`。
   - 目标：详情完整，但不进入高频轮询。

### 页面隐藏与恢复策略

当前页面进入 `document.hidden` 后，建议按停留时长分级：

1. 隐藏 `0-30s`
   - 维持低频轻量刷新，避免短暂切应用后回来明显断层。
   - 建议 `visible-live` 暂停，`selected-live` 可降到 `10s-15s`。

2. 隐藏 `30s-5min`
   - 暂停当前视窗实时刷新。
   - 只保留一次低频心跳或完全暂停。
   - 不更新视窗外飞机详情。

3. 隐藏超过 `5min`
   - 停止所有高频轮询。
   - 保留最后一次快照作为页面恢复时的占位数据。
   - 标记 `needsResumeRefresh = true`，但不累计请求队列。

用户回到页面时：

1. 立即刷新当前视窗 `visible-live`，只请求当前视窗内飞机的最小字段。
2. 如果有点选飞机，优先刷新 `selected-live`。
3. 首屏恢复完成后，延迟 `3s-8s` 再分批刷新 `offscreen-lite`。
4. 非视窗飞机最多分批更新，每批限制数量和字节预算，避免所有飞机位置同时快速跳动。
5. 过期请求全部丢弃，不允许隐藏前的旧请求覆盖恢复后的新视图。

### 地图缩放与拖拽策略

为了避免地图操作时出现明显迟滞：

1. 交互中不阻塞
   - 拖拽和缩放过程中只用已有缓存重绘。
   - 不等待接口返回后再移动飞机 icon。

2. 请求可取消
   - 每次视野变化生成新的 `viewportRequestSeq`。
   - 新视野请求发起后，旧视野请求直接取消或返回后丢弃。

3. 请求去抖和阈值
   - 地图 idle 后 `600ms-1000ms` 再发请求。
   - 中心点移动不足当前视窗宽高的 `15%-20%` 时不请求。
   - zoom 变化不足 `0.5` 时不请求，除非当前视窗没有缓存。

4. 预取少量边界
   - 当前视窗请求保留 `10%-15%` padding。
   - 不再使用过大的 padding，减少视窗外数据。
   - 用户小幅拖动时可以直接使用缓存，避免空白和卡顿。

### 数据返回策略

建议后端配合支持以下能力：

1. 当前视窗 minimal payload
   - 参数示例：`scope=viewport&payloadMode=minimal`。
   - 只返回地图绘制字段。

2. 非视窗 lite payload
   - 参数示例：`scope=offscreen&payloadMode=lite`。
   - 不返回机场信息、航迹、历史、机型详情。

3. 增量更新
   - 继续使用当前已有的 `sinceVersion`。
   - 有变化才返回更新列表。
   - 无变化返回极小响应或 `304`。

4. 字节预算
   - 服务端支持 `maxBytes` 或 `maxRows`。
   - 超出预算时按当前视窗、选中目标、屏幕中心距离排序返回。

5. 压缩
   - `513008` 必须启用 gzip/br。
   - 高频接口不返回重复字段名过多的冗余结构，必要时提供数组压缩结构或短字段版本。

### 前端缓存策略

1. 当前视窗缓存
   - 缓存最近 `2-3` 个视窗的 minimal 数据。
   - 用于拖拽回退、轻微缩放、短时间返回。

2. 非视窗缓存
   - 缓存较长，但标记为 `stale`。
   - 只用于显示，不参与高优先级实时判断。

3. 详情缓存
   - 飞机详情、机场详情、历史行程继续懒加载。
   - TTL 可从 `5min` 提升到 `15min-30min`，避免重复点选反复请求。

4. 恢复后渐进更新
   - 恢复可见时不一次性刷新所有缓存对象。
   - 先更新当前视窗，再按用户可能看到的顺序渐进刷新。

## 可执行优化方向

### P0：先降低持续型接口流量

1. 实时快照最小字段化
   - 地图渲染只需要：唯一键、经纬度、航向、高度、地速、注册号、航班号、机型代码、起降机场代码、状态、更新时间。
   - 机型详情、机场详情、历史行程、航迹明细继续按点选懒加载。
   - 后端建议支持 `fields=minimal` 或 `payloadMode=map`.

2. 飞机快照不要默认返回机场数据
   - `buildAircraftViewportRequest` 中将 `includeAirports` 改为 `false`。
   - 机场数据由 `refreshAirportData` 独立维护。
   - 如需保护选中机场或航线端点，只返回必要机场 code 与坐标。

3. 合并首屏重复请求
   - 初始化时避免 `refreshAirportData("init")` 和 `refreshRealtimeData("init")` 连续各打一遍完整 `513008`。
   - 首屏可以先请求一次组合快照，或先加载飞机，机场使用缓存/延迟加载。

4. 拉长普通轮询间隔
   - 不直接整体降频，而是按数据层级区分频率。
   - 当前视窗内飞机保持 `4s-6s`。
   - 点选飞机保持 `2.5s-4s`。
   - 当前视窗外飞机降到 `30s-60s`。
   - 页面隐藏超过 `5min` 后停止高频轮询，恢复时只刷新当前视窗。

5. 使用增量更新
   - 当前请求已传 `sinceVersion`，后端应返回变更集而非完整列表。
   - 无变化时返回 `304` 或极小响应。
   - 返回删除列表与更新列表即可，不必每轮返回全量飞机。

### P1：控制地图视野触发请求

1. 视野变化阈值
   - 当前地图 idle 后会触发 `refreshRealtimeData("viewport")`。
   - 增加阈值：中心移动不足视窗 20%、zoom 变化不足 0.5 时不发新请求。

2. 拖拽/缩放时只重绘本地缓存
   - 交互结束后再请求数据。
   - 当前已有 debounce，可进一步拉长到 `800ms-1200ms`。

3. 全局展示 icon 与全量请求解耦
   - 保留“所有缩放级别展示飞机”的体验。
   - 但低缩放不要每 4.2 秒请求全球全量详情，只请求低频 minimal 快照。

### P2：优化地图底图流量

1. 增加低流量地图模式
   - 默认仍可使用 Google Map。
   - 增加“低流量模式”：限制最大 zoom、降低地图细节、减少交互触发。

2. Leaflet 资源本地化/按需加载
   - Leaflet 目前作为降级能力，但默认仍外链加载。
   - 建议改为 Google 加载失败时再按需加载，或直接 vendor 到本地。

3. 静态资源压缩与缓存
   - `app.js`、`styles.css`、`data-service.js` 当前合计约 `913KB` 未压缩。
   - 线上应开启 gzip/br、强缓存、文件名 hash。

### P3：服务端压缩与缓存

1. 接口开启 gzip/br
   - `513008` 这类 JSON 列表接口必须开启 gzip/br。

2. CDN 或边缘缓存机场数据
   - 机场基础信息变化慢，可使用较长 TTL。
   - 停场数量可独立缓存，例如 `60s-300s`。

3. 拆分接口职责
   - 高频接口只返回动态位置。
   - 低频接口返回机场、机型、运营商、历史统计等稳定数据。

## 推荐实施顺序

1. 增加 `trafficDebug` 流量统计，先拿到真实字节量。
2. 将飞机快照拆成 `visible-live`、`selected-live`、`offscreen-lite` 三个逻辑通道。
3. 恢复可见时只刷新当前视窗，不补跑隐藏期间错过的请求。
4. 将飞机快照的 `includeAirports` 改为 `false`，合并或延迟首屏机场请求。
5. 推动后端支持 `fields=minimal`、`payloadMode=lite` 与 `sinceVersion` 增量响应。
6. 增加视野变化阈值、请求取消、恢复后分批刷新。
7. Leaflet 按需加载、静态资源压缩缓存。
