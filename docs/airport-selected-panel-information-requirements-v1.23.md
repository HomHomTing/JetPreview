# 机场选中面板信息陈列需求文档 1.23

## 1. 文档定位

本文档定义机场选中态下详情面板的信息陈列方式。参照 Flightradar24 的机场信息维度，但针对公务机运行特点重新组织。

建议归属版本：`1.23`。
形成日期：2026-08-17。

本版本只梳理需求与界面规范，暂不实施代码。

界面示例（可交互）：https://claude.ai/code/artifact/0e7619b1-e8be-4e89-b149-53bda8b6f9ae

数据来源限定为自有接口：`513008`、`513010`、`513014`、`513015`。不引入外部数据源，不露出 FR24 品牌、商标或会员文案。

## 2. 核心判断

FR24 的机场页以进出港航班列表为主体，因为定期航班的飞机几乎不长期停场。公务机相反。

`513010` 示例数据中，PEK 的 `groundInfo.groundNum` 为 **351**，而 `flightsInfo.sortiesEstimate`（今日预计起降架次）为 **15**；`513015` 示例中同一字段为 **35**。停场机队规模是当日流量的十倍量级。

结论：机场面板的第一段应为**停场**，而非进出港动态。这是本设计与 FR24 最主要的分歧点，也是「针对公务机运行特点」的直接体现。

## 3. 现状问题

### 3.1 停场列表硬截断

`app.js` 的 `renderGroundPlaneRows()` 写死 `planes.slice(0, 18)`，无分页、无「加载更多」。停场 351 架的机场有 333 架不可达。

这是本次要解决的首要问题。

### 3.2 停场时长数值被丢弃

`513014` 同时返回 `groundTime`（秒）与 `groundTimeStr`（如「今日入场」）。当前代码只读 `groundTimeStr`，全文件搜索 `groundTime` 无数值使用。

后果：无法排序、无法分层、无法回答「哪些是长期基地机、哪些是今天刚落地的」。

### 3.3 在途飞机混在停场列表中

`513014` 的 `groundPlanes[]` 含 `flightState: 30`（在途）记录。当前行渲染就地显示「途中」，但它仍占据停场列表一行，并被计入用户对停场数的感知。

### 3.4 注册号三态未做设计

`513014` 明确 `tailNoDisplay`「有三种情况：空 / 打码 / 明文」。当前 `firstMatchedValue()` 对空值回落为 `—`，打码值与明文同样式呈现。用户无法区分「没有这架飞机的号」与「这架飞机不公开号」。

### 3.5 513015 的运行统计全部闲置

`dailyStatistics`、`totalStatistics`、`popularModels`、`originAndDest` 四组数据在 `app.js` 中零引用。这是「近期运行记录查询」的现成数据源，无需新增接口。

### 3.6 停场构成数据未用

`513014.groundModels[]`（按机型聚合含 `count`）仅做简单摘要；`513010.groundInfo.groundDetal.brands[]`（按品牌聚合）零引用。

## 4. 信息架构

段序调整为五段，分段菜单置于面板**底部**：

| 段 | 回答的问题 | 主要内容 |
| --- | --- | --- |
| 停场 | 这里有哪些飞机 | 时长分层构成条、停场列表、构成视图 |
| 动态 | 今天什么情况 | 今日 KPI、进出港筛选、行程卡片列表、当地时间 |
| 运行 | 最近怎么样 | 近 15 天趋势、范围切换、机型排行、热门始发地/目的地 |
| 机场 | 能不能用 | 运行约束标签、报批政策、跑道与坐标 |
| FBO | 落地找谁 | 航站楼/FBO 联系方式、机场公告 |

### 4.1 底部分段菜单

分段菜单由顶部移至面板底部。理由：面板顶部已被机场码、限制横幅与标签行占据，再叠一层分段会把首屏挤满；底部更适合频繁切换，是拇指与光标的自然停留区。

| 项 | 规范 |
| --- | --- |
| 位置 | 面板最底部，常驻不随内容滚动；内容区在其上方独立滚动 |
| 底色 | `#212630`，**明显亮于面板底 `#14161a`**，形成独立控制层 |
| 分隔 | 顶部 1px `rgba(255,255,255,.11)` + 向上投影 `0 -8px 22px rgba(0,0,0,.42)` |
| 项结构 | 图标在上、文字在下，居中。图标 17px 线性描边，文字 10px |
| 未选中 | 图标与文字同为 `#7b8492` 中性灰 |
| 选中 | 薄荷文字与图标 + `rgba(61,224,192,.15)` 药丸底 + 1px 薄荷内环 |
| Hover | 文字转亮 + `rgba(255,255,255,.06)` 底色 |
| 触控高度 | 46px；移动端追加 `env(safe-area-inset-bottom)` |
| 无障碍 | 选中项带 `aria-current="true"`；焦点环 2px 薄荷内描边 |

关于「明显区分」：顶部分段与内容同底色时，用户容易把它读成标题而非控件。底栏换用更亮的独立底色加投影后，它在视觉层级上浮在内容之上；加上图标与选中药丸，点击指引由「靠一条下划线」变成「底色 + 图标 + 药丸 + 内环」四重叠加。

### 4.2 行程动态：机场大屏版式

动态列表按**机场航显大屏（FIDS）**的方式组织：固定列头、严格列对齐、时间列领衔、状态以实底色块呈现。大屏的设计目的是远距离快速扫读，与用户在地图上快速判断某机场当日节奏的诉求一致。

| 列 | 宽度 | 内容 | 规范 |
| --- | --- | --- | --- |
| 出发 | 52px | 出发时间 | 等宽 16px/600 + `tabular-nums`，是全表的排序锚点与视觉锚点 |
| 机号 / 航向 | 1fr | 三行：机号+方向徽标 / 航线 / 机场名+机型 | 机号等宽 13.5px；航线中**本场恒为弱化端** |
| 状态 | 76px | 状态色块 + 到达时间 | 右对齐；状态为实底色块而非描边 |

大屏特征的取舍：

| 项 | 规范 |
| --- | --- |
| 固定列头 | 顶部常驻 `出发 / 机号·航向 / 状态`，底色 `#252b36`，与行区分离 |
| 斑马纹 | 偶数行 `rgba(255,255,255,.028)`，长表在窄面板中防止串行 |
| 方向色条 | 每行左侧 3px：进港薄荷、出港浅蓝 |
| 状态实底 | 在途、延误、取消用实底色块（深色文字）；已到达与计划用中性底。**只有需要注意的状态是实底** |
| 不做的 | 不用翻牌动画、不用全大写英文、不模拟点阵字体。借鉴大屏的信息组织，不照搬视觉噱头 |

### 4.2.1 排序规则

**统一以出发时间升序（从早到晚）排列。**

- 出港的出发时间是本场推出时间；**进港的出发时间是始发地起飞时间**。这一点必须在表尾注明，否则用户会误以为进港行的时间是落地时间。
- 到达时间作为次级信息置于状态下方，标注「到达」（出港）或「落地」（进港）。
- 延误按**最新预计出发时间**排位，原计划时间以删除线附在其下。
- 取消仍按**原计划出发时间**排位，时间列显示带删除线的计划时间。若显示 `--:--`，它夹在两个正常时间之间会显得位置无来由。

### 4.2.2 方向与状态编码

| 维度 | 取值 | 视觉 |
| --- | --- | --- |
| 方向 | 进港 | 薄荷左色条 + 薄荷描边徽标，本场在航线右端 |
| 方向 | 出港 | 浅蓝左色条 + 浅蓝描边徽标，本场在航线左端 |
| 状态 | 在途 | 薄荷实底 + 深色文字 |
| 状态 | 已到达 / 计划 | 中性半透底，不上色 |
| 状态 | 延误 | 琥珀实底 + 时间列删除线原计划 |
| 状态 | 取消 | 珊瑚实底 + 整行 66% 透明度 |

方向用薄荷/浅蓝，状态用琥珀/珊瑚，两套编码互不冲突：方向色只出现在左色条与徽标，状态色只出现在状态块。同一行上不会有两处争夺注意力。

### 4.2.3 可读性规范

上一版存在大量小字与低对比灰，深色面板上难以辨认。本版做了系统性修订，并以脚本对全页 503 个文本节点做对比度审计。

| 项 | 旧值 | 新值 | 对面板底对比度 |
| --- | --- | --- | --- |
| 主文字 | `#f2f4f7` | `#f4f6f8` | 16.8:1 |
| 次级文字 muted | `#9aa3af` | `#b3bcc7` | 8.6:1 |
| 三级文字 muted-2 | `#6b7480` | `#8d97a4` | 5.9:1（旧 3.6:1 不达标） |
| 薄荷强调 | `#3de0c0` | `#4fe6c8` | 11.2:1 |
| 琥珀警示 | `#f0b849` | `#f5c463` | 10.4:1 |
| 珊瑚告警 | `#ff6b5a` | `#ff8272` | 6.8:1 |
| 底栏未选中项 | `#7b8492` | `#a6afba` | 6.5:1 |
| 分隔线 | `.07 / .13` | `.10 / .18` | 结构可辨 |

- 字号下限：面板内正文与标签**不低于 11px**（旧版存在 8–9.5px）；仅图表轴标签可到 9px。
- 达标线：正文 ≥ 4.5:1，大字（≥18px 或 ≥14px 粗体）≥ 3:1，按 WCAG AA。
- 验收：脚本遍历文本节点计算对比度，**浅色与深色主题均须 0 条不达标**。
- 禁止在正文中写死色值。示例中的「浅蓝」曾用固定十六进制，浅色主题达标、深色主题 3.1:1 不达标，已改为随主题翻转的类。

### 4.3 进港 / 出港筛选

| 项 | 规范 |
| --- | --- |
| 形态 | 三档分段控件 `全部 / 进港 / 出港`，置于 KPI 与列表之间 |
| 计数 | 每档直接显示条数，点击前即知规模；**三档之和等于全部** |
| 选中色 | 沿用该方向自身的颜色：进港薄荷、出港浅蓝、全部薄荷 |
| 排序 | 按时间升序，与方向无关；筛选不改变排序规则 |
| 切段重置 | 离开动态段再回来时筛选重置为「全部」 |
| 空态 | 某方向为 0 时该档仍可点，列表显示「当前筛选下没有行程」，不隐藏档位 |
| 数据来源 | 方向由行程的起降机场与本场比对得出；计数与 `flightsInfo` 的进出港口径保持一致 |

## 5. 停场列表设计规范

### 5.1 停场时长分层

| 层 | 判定（`groundTime` 秒） | 色条 | 运行含义 |
| --- | --- | --- | --- |
| 今日入场 | < 86,400 | 薄荷 | 流动过站，可能当日或次日离场，优先关注 |
| 7 天内 | 86,400 – 604,800 | 浅蓝 | 短期停场，多为公务行程间隔 |
| 30 天内 | 604,800 – 2,592,000 | 琥珀 | 长停，可能在维修或待运营 |
| 30 天以上 | ≥ 2,592,000 | 灰 | 基地常驻机，构成机场底盘 |
| 时长未知 | null / 0 | 虚线灰 | 不猜测，保留 `groundTimeStr` 原文 |

要求：

- 构成条以堆叠比例呈现，各层数字兼作筛选器。
- **「时长未知」层在存在该类记录时必须出现**。否则各层之和小于停场总数，用户会发现数字对不上。
- 分层阈值写入前端常量，便于按机场类型调整，不散落在判断里。
- 每行左侧 3px 色条标明所属层，滚动中不必回看分组标题。色条是行内唯一的颜色编码位，其余信息保持灰阶，避免数百行的色彩噪声。

### 5.2 注册号三态

| `tailNoDisplay` | 形态 | 主标题 | 可点击 | 计数 |
| --- | --- | --- | --- | --- |
| `"B-8302"` 明文 | 等宽白字 13px/600 | 注册号 | 是 | 计入 |
| `"T7***"` 打码 | 可见前缀白字 + 掩码转灰 + 「部分公开」虚线标 | 打码注册号 | 是 | 计入 |
| `""` 空 | 「未公开」虚线标，机型升为主标题 | 机型名称 | 是 | 计入 |

三态都必须可点击并计入统计。空值只代表**身份不公开**，不代表数据无效——机型、品牌、托管方、停场时长通常都在。当前渲染为 `—` 读起来像数据缺失，是语义错误。

### 5.3 在途机处理

- `flightState: 30` 的记录置于列表顶部「在途」独立小组，配薄荷徽标，可跳转实时航迹。
- 停场计数与分层统计**一律排除在途机**，避免同一架飞机既算停场又算在途。
- 在途组标题明示「不计入停场」。

### 5.4 行内信息与排序

| 位置 | 内容 |
| --- | --- |
| 第 1 行 | 注册号（或机型，见 5.2）+ 在途徽标 |
| 第 2 行 | `brandName` · `modelName` |
| 第 3 行 | `trusteeship` 托管方 · `serviceProvider` 运营方，二者不同时并列 |
| 右侧 | 停场时长（由 `groundTime` 格式化为 `3d` / `45d` / `7m`）+ 营运/未营运徽标 |

- 默认排序：停场时长升序（最新入场在前）。这是运行关注度顺序，不是接口返回顺序。
- 可选排序：时长降序、机型、托管方。
- 分段挂载：首屏 30 行，「加载更多」每次 +30，**移除 18 行硬截断**。
- 筛选：分层、关键词（注册号/机型/托管方）、营运状态。
- 构成视图：可切换为按机型（`groundModels`）或按品牌（`groundDetal.brands`）聚合，带占比条。

### 5.5 airbusRemark

`513014` 返回该字段但语义不明（示例值为「这是空客的备注」）。规范：若非空则在展开态以次级文字呈现，不进入行内常驻信息，不参与搜索，直到后端明确其含义与使用场景。

## 6. 特殊标签兼容规范

标签按**对运行的约束强度**分三级，而不是按数据来源分类。

### 6.1 三级分类

| 级别 | 视觉 | 含义 | 示例 |
| --- | --- | --- | --- |
| 限制级 | 珊瑚色实边，同时在头部出横幅 | 决定能否使用该机场 | 未开放外机、军民合用、军用机场 |
| 条件级 | 琥珀色 | 影响机型性能与机组资质，不阻断 | 高原、高高原 |
| 属性级 | 灰色描边 | 客观参数 | 4C、跑道数、海拔 |
| 未知值 | 虚线灰 | 原样透出，等待补充映射 | 后端新增取值 |

### 6.2 归一化映射

`type` 在两个接口取值不同：`513010` 为「民用」，`513015` 为「民用机场」。直接渲染会出现同一机场在不同段显示不同文案。

| 字段 | 已知取值 | 归一化标签 | 级别 |
| --- | --- | --- | --- |
| `type` | 民用 / 民用机场 | 不显示 | — |
| `type` | 军民合用 / 军民合用机场 | 军民合用 | 限制级 |
| `type` | 军用 / 军用机场 | 军用机场 | 限制级 |
| `openState` | 开放外机 | 不显示 | — |
| `openState` | 未开放外机 | 未开放外机 + 头部横幅 | 限制级 |
| `plateau` | 普通机场 | 不显示 | — |
| `plateau` | 高原 | 高原 | 条件级 |
| `plateau` | 高高原 | 高高原 | 条件级 |
| `grade` | 4C / 4E / 1B … | 原样 | 属性级 |
| 任意 | 未列出的取值 | 原样透出，虚线灰 | 属性级 |

### 6.3 兼容三原则

1. **默认态不占位**。「民用」「开放外机」「普通机场」是绝大多数机场的常态，显示它们等于给所有机场都挂标签，无信息量，一律不渲染。
2. **未知值不丢弃**。后端新增取值时前端必须原样透出，而不是判断失败后隐藏。
3. **归一化在适配层完成**。UI 只认归一化后的枚举，避免两个接口文案打架。

### 6.4 报批政策

`513015.approvalRules[]` 是公务机运行特有、FR24 没有的信息，含 `label` / `title` / `subtitle` / `contentHtml`。它与限制类标签是同一件事的两面：标签说「有约束」，报批政策说「约束是什么」。

| 项 | 规范 |
| --- | --- |
| 位置 | 「机场」段，紧随标签区，不折叠在最底部 |
| 关联 | 点限制类标签直接滚动到对应 `label` 的政策条目并高亮 |
| `contentHtml` | 后端返回 HTML 片段，**必须白名单过滤后再插入**，只允许 `p/br/ul/ol/li/strong/em/a`，`a` 强制 `rel="noopener"` |
| 缺失 | 数组为空时整块隐藏，不显示空标题 |

## 7. 近期运行记录

全部数据来自 `513015` 已返回但未使用的字段，不新增接口。

| 字段 | 内容 | 界面用法 |
| --- | --- | --- |
| `dailyStatistics` | 近 15 天进港/出港，各含计划、实际、取消 | 堆叠柱图，进港与出港双列，取消以珊瑚段叠在柱顶 |
| `totalStatistics` | 今日逐时、近 7 天、近 30 天，含总数/进港/出港 | 范围切换驱动同一张柱图 |
| `popularModels` | 执飞机型排行，today / 7d / 30d | Top 5 排行条，跟随范围切换 |
| `originAndDest` | 热门始发地与目的地，7d / 30d | 双列排行，机场码可点击跳转 |
| `flightsInfo` | 今日计划/实际/取消，进出港分列 | 三格 KPI：预计架次、执行率、取消数 |

### 7.1 派生指标

- 执行率：`(inboundActually + outboundActually) / (inboundPlan + outboundPlan)`。低于 70% 转琥珀，低于 50% 转珊瑚。
- 取消数：`inboundCancel + outboundCancel`。大于 0 以珊瑚显示，为 0 时显示 `0` 而非隐藏。
- 进出平衡：进港与出港差值。持续为正说明停场数在增长，与停场分层的「今日入场」互为印证。
- **不派生**准点率与延误时长——`513015` 未返回时刻，只有架次。

### 7.2 窗口口径不一致

`dailyStatistics` 是近 **15** 天，而 `totalStatistics` 与 `popularModels` 是 **7 / 30** 天，`originAndDest` 只有 **7 / 30** 天。界面若提供「7 天 / 30 天」切换，15 天这一组无法对齐任一档。

建议后端把 `dailyStatistics` 改为按 `rangeDays` 返回；在此之前，前端把它单独作为「近 15 天趋势」呈现、不参与范围切换，并在图上标注口径。本文按后者设计。

### 8.1 需后端确认的三项

| 项 | 说明 |
| --- | --- |
| 停场列表分页 | `513014` 一次返回全部 `groundPlanes`。351 架尚可，若某机场上千架则需 `page / pageSize`，并返回 `totalCount` |
| `groundTime` 基准 | 秒数需要明确的计算基准，否则跨时区与缓存场景下分层会漂移。建议同时返回 `serverNowEpochMs`，前端用它而非设备时间做分层 |
| `groundNum` 是否含在途 | **最需要先确认的一项。** `groundPlanes[]` 含 `flightState:30` 的在途机，那么 `groundNum`（示例 351）是否也把它们计入？若计入，则「停场 351」被高估，分层之和也无法与之对齐。需后端给出口径，或额外返回 `parkedNum` / `airborneNum` |

关于第三项：停场分层的全部数字都要与总数对账，用户一眼就会做加法。口径不明会直接导致界面上「各层之和 ≠ 总数」，这类数字不一致比缺失数据更损伤信任。在后端确认前，前端按「`groundNum` 含在途」假设实现，并在分层条外单独显示在途数，使两者可分别核对。

## 9. 验收标准

P0：

| 条目 | 判定方式 |
| --- | --- |
| 分段菜单位于面板底部且常驻 | 内容滚动时底栏不动；底栏底色与面板底色取值不同，可用取色验证 |
| 选中态四重指示齐备 | 选中项同时具备薄荷图标、薄荷文字、药丸底色、内环；触控高度 ≥ 44px |
| 动态列表为大屏版式 | 固定列头、三列对齐、斑马纹、方向色条、状态实底齐备；本场端弱化 |
| 按出发时间升序 | 时间列自上而下非递减；进港取始发地起飞时间，表尾注明口径 |
| 取消行程仍按计划时间排位 | 取消行显示带删除线的计划出发时间，不显示 `--:--`，且位置与该时间一致 |
| 对比度全量达标 | 脚本遍历全部文本节点，浅色与深色主题下不达标数均为 0；面板内字号 ≥ 11px |
| 进港/出港筛选可用且计数正确 | 三档之和等于全部；选中进港后列表内不存在出港行 |
| 方向与状态两套色不冲突 | 延误的进港卡上，方向徽标为薄荷、状态与时间为琥珀，二者同时可辨 |
| 停场列表可完整访问 | `groundNum` 为 351 的机场，通过「加载更多」可到达最后一行，无 18 行截断 |
| 停场时长分层与筛选可用 | 各层数字之和（含「未知」层）等于停场总数（排除在途），点任一层列表只剩该层 |
| 时长缺失的飞机有落点 | 存在 `groundTime` 为空的记录时，分层条出现「未知」层；不得出现各层之和小于总数 |
| 注册号三态各有形态 | 构造明文/打码/空三条记录，三者视觉不同且都可点击、都计数 |
| 在途机不计入停场数 | `flightState:30` 的记录在「在途」组，且不出现在各层统计中 |
| 限制类标签出横幅 | `openState` 为「未开放外机」时头部出现珊瑚横幅并说明后果 |
| 未知标签值不丢弃 | 注入未列出的 `type` 取值，界面以虚线灰标签原样显示 |
| `type` 归一化 | 「民用」与「民用机场」都不产生标签；两接口并存时不出现文案冲突 |
