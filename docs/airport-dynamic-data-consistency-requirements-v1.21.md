# 机场动态数据一致性需求文档 1.21

## 1. 目标

1. 机场动态面板的 KPI、方向筛选和行程列表使用统一数据口径。
2. 明确区分 `今日预计`、`实际进港`、`实际出港` 与 `已加载明细`，避免用户把统计总数理解为已完整返回的行程列表。
3. 当接口只返回统计、不返回完整明细时，界面必须提示缺口，不得伪造行程卡片。

## 2. 数据口径

| 展示项 | 优先字段 | 回退 |
| --- | --- | --- |
| 今日预计 | `flightsInfo.sortiesEstimate` | `inboundPlan + outboundPlan`、实际进出港合计、已加载明细数 |
| 实际进港 | `flightsInfo.inboundActually` | `inboundPlan`、已加载进港明细数 |
| 实际出港 | `flightsInfo.outboundActually` | `outboundPlan`、已加载出港明细数 |
| 全部筛选计数 | 实际进港 + 实际出港 | 已加载明细数 |

说明：

- `sortiesEstimate` 是预计/计划口径，不等于已返回行程明细条数。
- 方向筛选的 `全部` 必须等于 `进港 + 出港`，不能使用停场数量或其他统计口径补足。
- 停场数量不得参与机场动态 `今日预计` 或方向计数。

## 3. 明细展示规则

1. 行程列表只展示真实可得明细：实时在途匹配、`513015` 明细数组、`513014` 今日入场补充。
2. 如果统计总量大于可展示明细，在列表顶部显示缺口提示。
3. 缺口提示按当前筛选方向计算，例如进港筛选只提示进港明细缺口。
4. 如果今日预计大于实际进出港合计，提示尚未进入实际统计的预计架次。

## 4. 去重规则

行程去重必须使用行程级键：

```text
方向 + 注册号/航班号 + 起飞机场 + 到达机场 + 起飞时间 + 到达时间
```

禁止只用 `方向 + 注册号` 去重。否则同一架公务机同一天多段运行会被误删。

## 5. 非目标

- 不新增逐机场批量详情请求。
- 不恢复 `513012`。
- 不伪造缺失行程卡片。
- 不改动地图机场、飞机 icon 的加载逻辑。
