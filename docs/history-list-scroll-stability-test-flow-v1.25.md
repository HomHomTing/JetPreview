# 历史行程列表滚动稳定性测试流程 v1.25

## 目标

历史行程列表在任何重绘场景下，都不允许在顶部、中部、底部之间非用户触发地跳跃。列表刷新应保持用户当前阅读位置；只有明确点击“回到最新”、切换周期或首次进入行程 tab 时，才允许主动回到顶部。

## 测试环境

- 使用本地 HTTP 服务打开，不使用 `file://` 直接验证。
- URL 增加随机参数或更新静态资源版本，避免浏览器缓存旧 `app.js`。
- 选择历史行程不少于 120 段、底部存在“继续加载”的飞机。
- 记录以下观测值：
  - `scrollTop`
  - `scrollHeight`
  - `clientHeight`
  - 首个可见 `[data-history-flight-card]` 的 key 与距离滚动容器顶部的偏移
  - 当前渲染行数

## 通过标准

- 用户停止滚动后 8 秒内，`scrollTop` 不允许自动跳到 0 或最大滚动值。
- 非重置型重绘后，首个可见行程 key 应保持一致；允许因字体渲染产生 8px 以内偏移。
- 点击“继续加载”只允许追加列表，不允许自动跳到新增内容底部。
- 实时刷新或详情刷新时，若列表 HTML 未变化，不允许替换 DOM。

## 用例矩阵

1. 首次进入行程
   - 点选飞机，进入“行程”tab。
   - 期望：初始 `scrollTop = 0`。
   - 等待 8 秒。
   - 期望：仍保持 `scrollTop = 0`。

2. 底部加载更多
   - 滚动到列表底部。
   - 点击“继续加载”。
   - 期望：行数增加，视口停留在点击前附近的历史记录，不跳到新列表底部。
   - 向上滚动到接近顶部，等待 8 秒。
   - 期望：不回弹到底部。

3. 绝对顶部稳定
   - 在加载更多后滚动到 `scrollTop = 0`。
   - 等待 8 秒。
   - 期望：仍保持 `scrollTop = 0`。

4. 中部阅读稳定
   - 滚动到列表中部。
   - 记录首个可见行程 key。
   - 等待 12 秒，覆盖至少两轮实时刷新间隔。
   - 期望：首个可见行程 key 不变，不跳到顶部或底部。

5. 展开与收起行程卡片
   - 在中部点击一条行程卡片展开。
   - 期望：当前卡片仍停留在可见区域，不跳到顶部或底部。
   - 再次点击收起，重复验证。

6. 周期切换
   - 分别切换 `7d`、`30d`、`1y`。
   - 期望：这是明确重置场景，允许回到顶部。
   - 等待 8 秒。
   - 期望：顶部稳定，不回弹到底部。

7. 切换飞机
   - 在行程 tab 内切换到另一架飞机。
   - 期望：新飞机行程初始定位顶部。
   - 原飞机的滚动位置或加载更多状态不应影响新飞机。

## 当前修复策略

- 相同 HTML 不重复写入 `recentFlightsList`，减少长列表无意义 DOM 替换。
- 非重置型重绘使用首个可见行程记录作为滚动锚点，不再使用底部粘附。
- 程序性滚动恢复期间触发的 `scroll` 事件不视为用户滚动。
- 用户滚轮、触控、键盘滚动会废弃旧恢复任务，避免旧快照晚到覆盖新位置。
